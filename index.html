Omega Dental — a dental clinic in Dhaka

The brief

A clinic with no website, whose patients find it through Facebook and WhatsApp. It needed to be findable on Google, show prices openly, take appointments online, and cost nothing to run month to month.

What I built

A static site on GitHub Pages with a Firebase back end. Fourteen treatment pages, an open price list, a before-and-after gallery, a blog, and a careers page — every one of them in both Bangla and English from a single set of files.

Bookings that cannot go missing

An appointment written from the patient's browser reaches the clinic three ways: saved to the database the dashboard reads, emailed immediately, and swept again every five minutes from Google's own servers in case the patient's connection dropped mid-submit.

The owner edits it himself

Prices, services, gallery photos, doctor details and the homepage figures are all editable from a dashboard — no developer, no invoice, no waiting. A price change is live in under a minute.

The problem that shaped the build

The clinic owner opened the site and got a blank white page.

On a slow connection, the page rendered nothing at all. I reproduced it exactly: one decorative script — a QR code near the footer — was loading from a public CDN ahead of the site's own JavaScript. Deferred scripts run in order, so while that one CDN request hung, nothing after it ran. And because every visible word was being drawn by JavaScript, a hanging request for an ornament took the entire page down.

Fixing the script took an hour. Fixing the real problem took longer and mattered more: every one of the 28 pages now ships its words in the HTML itself. Turn JavaScript off entirely and the site still reads — all 28 pages, both languages, the full price list, all 53 gallery photos, the doctor's credentials. The scripts make it nicer. They are no longer load-bearing.

That is the difference between a site that demos well and a site that works in Mirpur at 6pm on mobile data.

How I work

Four things I will always do

  1. Quote the whole job before starting

    A fixed price for an agreed scope, and the running costs spelled out separately, so you know what year two looks like before you commit to year one.

  2. Put the domain in your name

    Your business is the registered owner. I keep the technical side, you keep the asset. If we ever stop working together, you lose nothing.

  3. Test the things that fail silently

    A booking form that stops working does not announce itself — it just goes quiet, and you assume business is slow. Those paths get tested on the real site, on the real domain, before handover.

  4. Build it so someone else could take over

    Plain HTML, CSS and JavaScript. No framework, no build step, no npm install. Any developer can clone it and start work — which is the point, because you should never be stuck with one person.
